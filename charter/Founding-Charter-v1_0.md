## ⭐ **1 — Purpose of the Charter**
This Charter defines:

- the **scope** of the Treaty Database  
- the **altitude boundaries**  
- the **non‑activation guarantees**  
- the **layer separation rules**  
- the **indexing system**  
- the **provenance requirements**  
- the **construction‑phase constraints**  

It ensures the Treaty Database acts as a **stable nexus** during NDH ecosystem construction, preventing collapse, drift, or cross‑layer contamination.

## ⭐ **2 — Altitude & Activation Rules**
### **2.1 Altitude Neutrality**
The Treaty Database operates at **ΔAltitude = 0**.  
It does not elevate or descend into any NDH layer.

### **2.2 Non‑Activation Clause**
The Database must **never** activate:

- geometry  
- gates  
- apertures  
- posture  
- recursion  
- substrate dynamics  
- constellation routing  
- governance altitude  

It is a **coordination repository**, not an operational system.

---

## ⭐ **3 — Layer Separation Mandate**
The Treaty Database stores MOUs across five distinct layers:

1. **Expressive Layer (MOU‑E0)**  
2. **Structural Layer (MOU‑S0)**  
3. **Substrate Layer (MOU‑SUB0)**  
4. **Constellation Layer (MOU‑C0)**  
5. **Meta‑Governance Layer (MOU‑M0)**  

Each layer must:

- remain sealed  
- remain altitude‑bounded  
- reference only the layer below  
- never activate the layer above  
- maintain provenance anchors  

This prevents cross‑layer collapse.

---

## ⭐ **4 — Indexing System**
The Treaty Database uses a **strict index‑first architecture**:

- **MOU‑E0.json** — Expressive  
- **MOU‑S0.json** — Structural  
- **MOU‑SUB0.json** — Substrate  
- **MOU‑C0.json** — Constellation  
- **MOU‑M0.json** — Meta‑Governance  

All MOUs must be:

- indexed  
- altitude‑tagged  
- provenance‑anchored  
- freeze‑sealed  
- non‑activating  

Indexing prevents drift and ensures safe referencing.

---

## ⭐ **5 — Construction‑Phase Constraints**
During NDH ecosystem construction:

- MOUs must be added **progressively**, not all at once  
- each MOU must be altitude‑checked  
- each MOU must include a non‑activation clause  
- each MOU must include a freeze seal  
- each MOU must reference the Founding Charter  
- ontology work must not begin until MOU‑C0 and MOU‑M0 are stable  
- hyperstructure routing must not begin until MOU‑S0 is stable  

This ensures Mission Control stabilizes before Launch Pad activation.

---

## ⭐ **6 — Provenance Requirements**
Each MOU must include:

- version  
- maintainer  
- altitude  
- dependencies  
- non‑activation clause  
- freeze seal  
- timestamp  
- location  

This ensures traceability and prevents accidental activation.
